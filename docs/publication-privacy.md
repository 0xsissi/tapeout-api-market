# 发布前的隐私检查

公开身份统一使用 GitHub 账号 `0xsissi`。文档使用仓库相对链接，本机文件位置使用 `~/.clawmarket/...`；测试使用临时目录或 `/fixture/...`。

发布客户端前自动检查已跟踪文件和打包内容。也可以手动执行：

```sh
pnpm privacy:check
node scripts/check-privacy.mjs --staged
```

通过本地环境变量 `TAM_PRIVATE_TERMS` 设置额外禁止公开的词，以逗号分隔。不要把实际名单提交到仓库。检查只报告文件名和问题类别，不打印匹配到的内容。

钱包、API/AI 接入令牌、上游登录资料和服务器配置放在仓库外；`.gitignore` 同时排除这些运行时文件。令牌路径的显示使用 `~`，实际文件位置和权限保持不变。

公开源码不包含运营者 IP、SSH 登录信息、部署节点身份、个人钱包或联调截图。节点地址通过私有环境配置和运行时公开发现列表提供；合约地址及测试币参数是公开接入信息。`report/` 下的运行证据留在本机，不提交。

公开仓库从清理后的当前源码创建一条初始提交，提交身份只使用项目的 GitHub 用户名及 noreply 邮箱。旧历史、PR 资料和完整备份放在仓库外。不能把旧镜像或旧分支推回公开仓库。

发布检查包含全部候选文件、已知私钥与登录令牌的精确匹配，以及独立凭据模式扫描。测试使用的模拟地址、示例邮箱和测试密钥不代表实际账户，不能向测试密钥对应的钱包充值。第三方依赖的原始版权和许可证须保留。

截图需人工检查用户名、邮箱、令牌和本机路径，文本扫描不能识别图片中的字。若历史记录曾包含个人信息，仅修改最新文件无法清除旧提交；需要备份并清理相关分支的历史。旧提交缓存及拉取请求中的残留由 GitHub 支持处理，参见 [GitHub 隐私数据清理说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)。
