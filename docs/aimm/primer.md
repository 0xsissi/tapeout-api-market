# AIMM Primer — 从零开始理解"自动化推理做市商"

> 读完本文你会知道：**AIMM 是什么、为什么需要它、它怎么定价、怎么防止网络故障，以及它和 AMM 的关系**。
>
> 目标读者：懂一点 DeFi（知道 Uniswap/AMM）、也懂一点 AI（知道什么是推理/token）的人。
>
> 阅读时间：15 分钟。

---

## 1. 一句话先讲清楚

**AIMM（Automated Inference Market Maker，自动化推理做市商）是一种让 AI 推理能力像资产一样被做市的链上协议。**

- **AMM** 解决的问题是："我想把 ETH 换成 USDC，不想挂单等对手方"
- **AIMM** 解决的问题是："我想调用 Claude 推理 1000 tokens，不想签订阅、不想走中心化 API"

它们共用一个设计哲学：**用一条自动曲线取代中心化撮合**。

---

## 2. 为什么需要 AIMM

### 2.1 现在买 AI 推理是什么样的

今天你要用 Claude / GPT / Gemini，只有两条路：

| 方式 | 问题 |
|---|---|
| 官方订阅（ChatGPT Plus / Claude Max） | 用不完会浪费；超额会被限流；封号就没了 |
| 官方 API（按 token 计费） | 要绑信用卡；对开发中国家不友好；价格官方说了算 |

于是世界上出现了两群痛苦的人：

- **A 群体**：订阅了但用不完的人——每个月交 20 美元，实际用 30%，**剩下 70% 就蒸发了**
- **B 群体**：想用 AI 但付不起或不方便付的人——被地域限制、被信用卡门槛挡在门外、或单纯想要更便宜的价格

**A 群体有供给，B 群体有需求，但中间没有市场。**

### 2.2 中心化的"转售平台"为什么做不成

有人尝试过中心化的转售（把 A 群体的 API key 卖给 B 群体），但三个死穴：

1. **违反服务条款**：平台方要承担法律风险
2. **账号池管理**：成百上千个账号的健康状态、额度、延迟，中心化服务器撑不住
3. **信任问题**：B 付钱给平台，平台给不给 A 分账？A 被封号了谁兜底？

中心化方案注定做不大。需要一个**无须信任、点对点、链上结算**的协议——这就是 AIMM。

## 3. AIMM 的核心机制：CUC 定价曲线

### 3.1 先看 AMM 是怎么做的

Uniswap 的天才在于一个公式：

```
x * y = k
```

（x 和 y 是池子里两种代币的储备量，k 是常数）

有了这个公式，**不需要挂单簿、不需要撮合引擎**，价格自动由储备比例决定。你买得越多，储备越少，价格自然越贵。

**AIMM 要做的事情完全一样，只是把"储备"换成"容量"。**

### 3.2 AIMM 的公式：CUC

核心公式只有一行：

```
p(u) = p₀ / (1 - u)^α
```

翻译成人话：

- **p** = 当前这笔请求的报价（USDC / 百万 tokens）
- **p₀** = 做市商（卖家）设的底价——"最低我也要赚这么多"
- **u** = 当前容量利用率——"我这单生意被占用了多少"（0 = 完全闲置，1 = 满载）
- **α** = 做市商自选的斜率——"我想多快地涨价"

### 3.3 这个公式长什么样

举个例子，一个 Claude 做市商设 `p₀ = $2 / 1M tokens`, `α = 1`:

| 当前利用率 u | 报价 p | 意味着 |
|---|---|---|
| 0（完全闲置） | $2.00 | 底价，抢单阶段 |
| 0.25（四分之一） | $2.67 | 略有需求 |
| 0.5（半满） | $4.00 | 生意不错 |
| 0.75（四分之三满） | $8.00 | 稀缺资源，涨价保留 |
| 0.9（快满了） | $20.00 | 只服务愿意付钱的人 |
| 0.99（满了） | $200.00 | 接近拒绝 |

**效果**：

1. **闲的时候自动降价**——快速吸引买家
2. **忙的时候自动涨价**——保留容量给愿意付的人
3. **永远不会崩**——u 趋近 1 时价格趋近无穷，天然限流

这就是 AIMM 的 `x * y = k`。

### 3.4 为什么是 `1/(1-u)^α` 而不是别的

我们考虑过几种形式：

- **线性** `p = p₀ (1 + u)`：u=1 时也只翻倍，起不到限流作用 ❌
- **指数** `p = p₀ e^(αu)`：数学上 OK，但 u=1 时价格不是无穷，不能当硬上限 ❌
- **倒数型** `p = p₀ / (1-u)^α`：u→1 时 p→∞，**完美充当"保险丝"** ✅

这也是 Uniswap `x*y=k` 的同源逻辑——储备 → 0 时价格 → ∞。

## 4. 四根柱子：完整协议长什么样

光有公式不够。一个能跑的协议需要回答四个问题：

### 柱 1：定价（Pricing）
**问题**：价格谁定？
**答案**：做市商注册时声明 `{模型, 容量 C, 底价 p₀, 斜率 α}`，协议按 CUC 算实时价。

### 柱 2：路由（Routing）
**问题**：一笔买家请求送到哪个做市商？
**答案**：协议从所有匹配的做市商拉实时报价，选综合得分最优的（价格 × 延迟 × 可靠性）。

### 柱 3：结算（Settlement）
**问题**：USDC 怎么从买家到卖家？
**答案**：买家先把 USDC 存进 `EscrowPool` 智能合约；每笔请求产出签名的"使用凭证"；做市商累积一批凭证后，一次性上链 claim，合约自动转账。

### 柱 4：信誉（Reputation）
**问题**：新做市商和老做市商怎么区分？
**答案**：每笔结算自动更新做市商的成功率、延迟、在线时长。评分影响路由权重，低分自然被淘汰。

## 4.5 买家视角：AIMM 的 UX 承诺

读到这里你可能会问：**那买家用 AIMM，还是得自己从市场找卖家吗？**

**不是。这恰恰是 "Automated" 的关键——买家不参与找卖家。**

### 没有 AIMM 的 P2P 市场长什么样
```
买家 → 打开页面 → 看 50 个卖家列表 → 比价 →
手动选 → 担心跑路 → 下单 → 垃圾结果 → 投诉无门 → 换家重来
```
这就是为什么大多数 P2P 市场起不来——**买家认知负担太重**。

### 有 AIMM 的买家操作
```bash
claw chat --model claude-sonnet "帮我写个爬虫"
```
就这一行。**中间的 50 个做市商、CUC 报价、路由决策、信誉加权、USDC 结算，全部由协议自动完成。买家看不到也不用管。**

### 买家实际看到的

```
✓ Connected
  Routed to maker: 0x3af2…c81 (reputation 0.94)
  Estimated price: $2.34 / 1M tokens
  Max slippage: 5%

[流式返回答案...]

✓ Done. Used 3,421 tokens → $0.008 settled via EscrowPool.
```

### 协议在毫秒内完成的

1. **Discovery**：通过 libp2p 发现在线 maker
2. **Quote 收集**：向匹配模型的 maker 拉实时 CUC 报价
3. **评分**：`综合得分 = 价格 × 延迟 × 信誉`
4. **路由**：softmax / 贪婪选一个
5. **加密会话**：和选定 maker 建立 E2EE 通道
6. **记账**：产生带双方签名的使用凭证
7. **兜底**：超时 / 失败自动 fallback 到下一个

### 和 Uniswap 是一回事

| 步骤 | Uniswap 用户 | AIMM 买家 |
|---|---|---|
| 用户动作 | "把 1 ETH 换 USDC" | "用 Claude 生成这段代码" |
| 用户看到的 | 一个价格、一个按钮 | 一个报价、一个流式输出 |
| 协议背后做的 | 从 N 个池子找最优路径 | 从 N 个 maker 路由最优 |
| 用户需要认识 LP/Maker？ | ❌ 不需要 | ❌ 不需要 |

### 高级用户出口

默认全自动。但保留手动挡给企业/开发者：

```bash
claw chat --maker 0x3af2…c81 "..."       # 钉一个 maker
claw chat --prefer-latency "..."          # 优先低延迟
claw chat --prefer-price "..."            # 优先低价
claw chat --max-price 3.0 "..."           # 硬上限
```

95% 的个人用户永远不用这些选项。

### 市场 Dashboard 给谁看

- **做市商**：看自己在深度图的位置，调整 p₀/α
- **分析师**：看 AIMM 整体健康度
- **AI agent（V3）**：通过 API 查深度用于自动决策

**买家**打开 Dashboard 只是满足好奇心，不是用来下单。

### 一句话承诺

> **买家不找市场，市场找买家。**
> **AIMM 的价值 = 让买家忘记 maker 存在。**

这是 AIMM 区别于 OpenRouter（中心化聚合）、裸 P2P 市场（认知负担）、官方 API（无选择）的核心 UX 承诺。

## 4.6 分布式发现机制：Gossip + 本地缓存

上一节讲"买家不找 maker"，但**协议层面到底怎么做到的**？很多人第一反应是：
- "是不是有个调度中心？"（那就中心化了，违背 AIMM 初衷）
- "还是买家每次请求都全网询价？"（N 次网络往返，慢到没法用）

**两个都不是。AIMM 用的是第三种模式：推送 + 本地缓存。**

### 工作原理
```
[持续后台] Makers ──gossip──▶ 全网广播签名报价（每 10 秒一次）
                                       │
                                       ▼
[每个 Buyer] 本地维护"报价表"（LocalQuoteCache）
             - 过期自动清理（TTL 10s）
             - 按模型索引
                                       │
[请求时刻]  Buyer ──从本地表选──▶ Maker（一次 P2P 连接）
```

### 三种架构的延迟对比

场景：100 个 Maker，Buyer 已在线 1 分钟

| 架构 | 选 Maker 耗时 | 下单耗时 | 总时延 |
|---|---|---|---|
| 中心调度器 | 1ms | Buyer→Scheduler→Maker（~400ms） | ~400ms |
| 每次全网询价 | 200ms × 100 = **20s** ❌ | 200ms | ~20s ❌ |
| **推送+缓存（AIMM）** | **0ms（本地）** | Buyer→Maker（~200ms） | **~200ms** ✅ |

**AIMM 比中心调度器还快**——省掉了 Scheduler 这一跳。

### 现实世界的同类架构

这不是新发明，P2P 系统用这模式几十年了：

| 系统 | 工作方式 |
|---|---|
| 股票交易所 Level 2 行情 | 推送 order book 更新，终端维护本地簿 |
| BGP 路由 | 路由器间 gossip，本地决策转发 |
| Uniswap Router | 链上池子状态公开，Router 读本地 RPC |
| Kademlia DHT | Gossip 维护路由表，查询无需全网扫描 |
| 以太坊 Mempool | 全网 tx gossip，矿工本地排序 |

### 边界情况

- **新 Buyer 冷启动**：从 bootstrap peer 拉一次快照，1-2 秒完成
- **网络分区**：Buyer 只看到子网内 Maker，可能错过更优价，但不致命
- **Quote 过期**：Maker 不响应过期 Quote，Buyer 本地清理后重选
- **Gossip 传播延迟**：libp2p GossipSub 实测 <500ms，10s TTL 里毫无压力

### 可选的辅助节点（非协议一部分）

类似 Etherscan 之于以太坊——**不参与共识、谁都能跑**：

- **Bootstrap Node**：帮新节点冷启动
- **Analytics Node**：抓历史 Quote 做 Dashboard
- **Fallback Router**：网络差的用户的热备

这些让体验更好，但协议不依赖它们。

### 一句话

> **AIMM 不是"每次请求全网比价"。**
> **AIMM 是"后台持续接收全网报价广播，请求时从本地缓存秒选"。**
>
> **零调度中心，零请求级网络查询。**

## 5. 防止网络翻车：羊群效应和它的解药

### 5.1 天真版本的问题

如果我们真的傻傻地"实时算价 + 路由给最便宜的"，会发生什么？

```
时刻 t=0：卖家 A 最便宜 → 所有请求砸向 A
时刻 t=1：A 的 u 瞬间 0→0.9 → A 价格暴涨
时刻 t=2：所有请求切到 B → B 重复同样命运
时刻 t=3：所有请求切到 C → ...
时刻 t=4：市场震荡，价格没有稳定点
```

这就是**羊群效应（Thundering Herd）**。网络拥堵、价格失真、买家体验崩盘。

**必须从协议层面堵住。**

### 5.2 四个解药（全部有 DeFi 前例，不是我们发明的）

#### 解药 1：报价 TTL（Time-To-Live）
做市商不是实时报价，而是**每 10 秒广播一次带签名的报价**。这个报价在 10 秒内有效、不可反悔。

- 好处：价格不会在买家选定和请求送达之间变化
- 类比：Flashbots 的 slot-by-slot 拍卖、CowSwap 的批量窗口

#### 解药 2：概率路由（Softmax Routing）
不要贪婪选最便宜的。用概率分布：

```
P(路由到卖家 i) = (1/价格_i)^β / Σ(1/价格_j)^β
```

β 是温度参数。β≈3 的时候：最便宜的拿 ~70% 流量，次便宜的拿 ~20%，剩下分散到其他。

- 好处：流量自然分散，不会瞬间坍缩到单点
- 类比：ML 里的 temperature sampling、负载均衡的 WRR

#### 解药 3：EWMA 平滑
用移动平均的 u 而不是瞬时 u：

```
u_quote = 0.7 × u_现在 + 0.3 × u_过去60秒平均
```

- 好处：短期抖动不触发价格过冲

#### 解药 4：冷启动坡道
新做市商前 24 小时容量上限 = 声明容量 × 10%，服务稳定后逐步放开。

- 好处：新人不会被瞬间打爆、老节点有溢价

### 5.3 什么时候羊群真的会咬人

做一次量化估算：

| 阶段 | 并发请求 / 秒 | 每个做市商 req/s | 羊群风险 |
|---|---|---|---|
| V1 启动期 | 0.5~2 | 0.05~0.2 | 🟢 **太小，不触发** |
| 增长期 | 10~50 | 0.1~0.5 | 🟡 需要解药 1+2 |
| 规模期 | 500+ | 1+ | 🔴 解药 1-4 全上 |

**V1 你不会遇到羊群**。但协议设计必须**预埋接口**，不然长大后改不动。

## 6. AIMM 的衍生术语（行业词即将诞生）

AMM 真正火的不是公式本身，而是它衍生出的一整套词：**Slippage、Impermanent Loss、LP Token、TVL**。每个都成为了行业标准。

AIMM 也要有自己的衍生词。这是四个核心的：

### 6.1 Inference Slippage（推理滑点）
买家下单时看到的价格和实际成交价的差。长 prompt 生成过程中 u 在变，价格会爬升。

> "Your 5000-token generation had 8% inference slippage — the maker's capacity filled mid-generation."

### 6.2 Capacity Decay（容量衰减）
做市商的订阅额度每天/每周重置，**未卖出的容量归零**。这是 AIMM 独有的时间压力，Uniswap LP 没有。

> "AIMM makers face daily capacity decay. Unsold quota evaporates at reset."

### 6.3 Quote Depth（报价深度）
在某个价格水平 p* 以下，全网累计可供应容量。类比订单簿深度，但由 CUC 自动生成。

> "At 1.5× base price, Claude-Sonnet has 2.3M tokens/hr of quote depth."

### 6.4 Maker TTL（做市商存活周期）
一个做市商账号从上线到被耗尽（订阅打完或被封号）的平均生命周期。AIMM 独有的风险指标。

> "Codex maker TTL is ~14 days, then accounts rotate."

更详细的定义看 `glossary.md`。

## 7. 三阶段路线图

**诚实分阶段比假装一步到位更能建立信任。**

### Phase 1（V1，现在就上）：AIMM V1 已落地
- 做市商手动设 p₀ 和 α，CUC 按 `u_window` 动态报价
- 10 秒报价窗口 + u 跳变事件广播
- Buyer 侧 Quote cache + softmax 路由
- Reject-with-Quote、429 cooling、熔断、反重放、时钟容忍、metrics 已接入
- AIMM TestKit + A-F 对照实验已提供，真账号 smoke/24h chaos 作为上线 gate 执行

**能落地的原因**：核心路径已经压到本地报价缓存、纯函数定价、可复现实验和最小 metrics，真实账号 gate 只负责最终上线验收。

### Phase 2（V2，6-9 个月后）：动态路由 + 信誉系统
- EWMA 平滑的 u
- 冷启动坡道
- 链下信誉评分、链上 commitment
- 更细粒度的 reputation decay / Sybil 防护

**需要条件**：并发到百级/秒、做市商数量超过 50。

### Phase 3（V3，12-18 个月）：抗操纵 + 参数自适应
- 自成交检测
- 链上信誉证明
- α 和 β 根据历史需求自动调整
- 跨模型套利通道

**需要条件**：协议成熟，有持续作恶经济动机出现。

## 8. FAQ

### Q1：CUC 和传统订单簿有什么本质区别？
订单簿需要买卖双方同时挂单等撮合。CUC 是**卖家一次性声明规则**，价格随需求自动变化，买家发来就成交。更像"自动售货机"而不是"拍卖会"。

### Q2：做市商可以联合操纵 α 来抬价吗？
理论上可以，但：
1. 市场多做市商竞争，联合代价高
2. 买家看得到全网报价深度，异常价格会暴露
3. V3 会加入反联合检测

短期靠市场竞争压制，长期靠链上证据打击。

### Q3：不同模型的容量能混在一个池子吗？
**不能**。Claude 的能力和 Codex 的能力不是同质化资产。AIMM 的"池"是**每个模型一个**（或每种能力一个），用 `{model_id, capability_tag}` 作为 key 分开维护。

### Q4：推理的实际结果质量怎么保证？
CUC 只管定价和路由。质量通过**信誉层**处理：
- 每笔请求买家可以打分（成功/失败/质量异常）
- 低质量做市商 reputation 掉，路由权重降低
- 极端情况可以发起链上争议，EscrowPool 留有争议期

### Q5：这和 OpenRouter 有什么区别？
OpenRouter 是中心化路由聚合器，需要它自己签 API 商业协议、需要 KYC 接入。AIMM 是：
- **无许可**：任何人可当做市商，不用签合同
- **链上结算**：USDC 直接到做市商钱包，不经中间账户
- **价格发现**：CUC 自动定价 vs OpenRouter 的固定加价
- **抗审查**：没有中心化实体能"拔插头"

### Q6：买家怎么相信做市商真的在跑 Claude 而不是套壳垃圾模型？
这是未来的"proof of inference"研究方向。V1-V2 靠**信誉 + 抽查**：
- 协议定期发送已知 ground-truth 的测试 prompt
- 做市商响应偏离预期则扣信誉
- 买家端也可以做 shadow test

### Q7：这个东西合法吗？
AIMM 协议本身是中立的软件，和 Uniswap 同样性质。**个人共享自己的订阅容量**在大多数服务条款里是灰区，但属于个人行为。协议不代任何人承担合规责任——这和 P2P 文件共享、VPN 的定位一样。

## 9. 为什么 AIMM 一定会出现（而不是延续中心化）

三个历史类比：

| 场景 | 中心化方案 | 去中心化方案 | 结果 |
|---|---|---|---|
| 支付 | 银行 SWIFT | 比特币/稳定币 | 共存，去中心化吃增量 |
| 交易 | 券商/交易所 | DEX/AMM | Uniswap 超过多数 CEX 交易量 |
| 存储 | AWS S3 | IPFS/Filecoin/Arweave | 仍在早期但趋势确定 |
| **AI 推理** | **OpenAI/Anthropic/OpenRouter** | **AIMM** | **我们在这里** |

每一个赛道的共同规律：**中心化先跑出来**（因为资本效率高），**去中心化后跑出来**（因为抗审查、透明、用户拥有）。AI 推理市场正处在这个转折点。

**AIMM 不是要取代 OpenAI，是要成为 OpenAI 之外的那条路。**
